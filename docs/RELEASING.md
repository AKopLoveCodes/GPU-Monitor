# Releasing GPU Monitor

This repository is prepared for source releases. A release contains the versioned source
archive generated by GitHub plus release notes; it does **not** bundle NVIDIA drivers or
`nvidia_gpu_exporter` binaries. The application downloads and verifies its supported
exporter on first start, or accepts `GPU_MONITOR_EXPORTER` for a user-supplied build.

## Compatibility matrix

| Area | Supported release target | Notes |
| --- | --- | --- |
| Local macOS | Yes | Apple Silicon currently runs the pinned x86_64 exporter through Rosetta. |
| Local Linux | Yes, command-line path | CI and unit tests cover Linux; real-hardware validation is still recommended. |
| Local Windows | No | Use a POSIX environment only; native Windows is unsupported. |
| Remote GPU host | Linux + NVIDIA driver + `nvidia-smi` | No agent, package or port is installed remotely. |
| Python | 3.9+ | Python uses only the standard library. |

## Before creating a release

1. Ensure the worktree is clean and run the checks below.
2. Update `CHANGELOG.md`, `pyproject.toml`, `setup.py` and `CITATION.cff` to the intended version.
3. Verify README requirements and known limitations still match the release.
4. Create an annotated tag such as `v0.1.0`, then push the branch and tag after a GitHub
   remote exists.
5. On GitHub, create a Release from that tag, paste the relevant changelog section and
   state the compatibility matrix and known limitations above.

```sh
python3 -m unittest discover -s tests -v
node tests/test_ui_logic.cjs
python3 -m py_compile server.py scripts/*.py
git tag -a v0.1.0 -m "GPU Monitor v0.1.0"
```

Do not attach a real `config.json`, `.runtime/`, `.tools/`, logs, SSH settings or screenshots
that expose host names, user names or process command lines.
